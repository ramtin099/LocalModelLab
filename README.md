# LocalModelLab

Phase 1A: reproducible local inference benchmarks using .NET 8 and Ollama. Four projects, sequential execution, independent attempts, immutable run snapshots, streamed answer/reasoning capture, raw responses and Markdown/CSV reports. No generated-code execution, quality scoring or model ranking.

From the repository root, with a .NET SDK supporting net8.0:

```powershell
dotnet build LocalModelLab.sln -c Release
dotnet test LocalModelLab.sln -c Release
dotnet run --project LocalModelLab.Cli -c Release -- models list
dotnet run --project LocalModelLab.Cli -c Release -- cases validate
dotnet run --project LocalModelLab.Cli -c Release -- benchmark run --models granite4:3b --suite smoke --profile smoke
dotnet run --project LocalModelLab.Cli -c Release -- benchmark report --run "results/RUN_ID"
dotnet run --project LocalModelLab.Cli -c Release -- benchmark inspect --run "results/RUN_ID" --attempt 000002
```

Use exact installed model names from `models list`; the harness never pulls models. For multiple models, pass `--models "model:tag,other:tag"`. Use `--help` for all options. Test execution requires no running Ollama server. Production uses only .NET libraries; xUnit and the test SDK are test-only dependencies.

Results are local and gitignored. A validated run directory contains `manifest.json`, `definitions.json`, `selection.json`, `schedule.json`, `state.json`, and `attempts/000001/{request.json,response.raw,result.json}`. Reports get their own new directory on each generation. Completed inference artifacts are never regenerated or resumed. `Ctrl+C` preserves the active attempt; forced termination leaves its raw bytes and an `inProgress` marker.

The Ollama adapter follows the upstream [chat contract](https://docs.ollama.com/api/chat), [model discovery contract](https://docs.ollama.com/api/tags), and [capability/thinking types](https://github.com/ollama/ollama/blob/main/api/types.go). Requested thinking values require explicit model support; unsupported or unknown settings are never automatically substituted. Server-internal effective values that Ollama does not expose remain unknown.

Hardening release: harness 1.1.0, artifact schema 1. Existing profiles retain `modelFirst` scheduling and `providerManaged` residency. Opt in through profile fields `scheduling: "rotating"` and `residency: "singleModel"`; `benchmarks/comparison.v1.json` supplies both. The exact schedule is persisted before inference. New profile fingerprints include these fields, even at default values; do not equate them with fingerprints generated by 1.0.0. This reader accepts older artifacts; older strict readers may reject new additive fields.

`singleModel` explicitly unloads other resident models, including models outside the selected set. Use a dedicated Ollama server. It verifies pre/post snapshots, preserves provider load duration, and fails when exclusivity cannot be observed. Sequential inference alone does not establish exclusive residency. Neither policy flushes OS caches or guarantees warm inference.

Preflight failures after run creation retain definitions, selection and final state with `phase`, `failureKind` and error. A manifest exists only after successful preflight. Inspect/report support these incomplete runs. CLI syntax, unreadable/malformed input, invalid endpoint and machine discovery cancellation can fail before run creation and leave no run directory. Storage failure or forced termination can still prevent final evidence.

GitHub Actions builds and tests on Windows and Ubuntu using .NET 8; mocked HTTP tests require no Ollama. Machine metadata is static inventory; timestamped `/api/ps` observations are residency snapshots. GPU/CPU utilization, peak VRAM and energy are explicitly not collected. See the [measurement contract](docs/comparison.md#measurement-evidence).

The separately versioned [Non-Thinking comparison](docs/comparison.md) provides a 512-token two-model smoke and a 2048-token four-model full run. Reports distinguish completed execution from empty/reasoning-only answers without scoring or changing attempt status.
